# Lumen design and product rules

The one reference for how Lumen looks, behaves and what it must keep doing. It replaces the old DESIGN, PRODUCT,
UX-CONTRACT, design-foundation, motion-audit and brand notes (all in git history before `chore/cleanup-ux-pass`).
Owner decisions that override anything here are listed in [HANDOFF.md](HANDOFF.md) → Decisions.

## Product

Lumen is a private AI workspace: chat, documents, data analysis and GitHub coding, with free and bring-your-own-key
models routed per message. Phone and desktop are equal citizens. Live at https://lumen-chat.web.app.

- **Accounts and keys.** Google sign-in, invite-only (`firestore.rules`). Provider keys are saved privately per
  account (Router → provider page). A saved key never authorizes a request on its own: paid-capable providers start
  disabled and need their credit/charge consent saved. NVIDIA and Cloudflare go through the app-owned relay
  (`server/provider-relay`); the relay stores nothing. GitHub Models was retired 2026-07-30.
- **Routing.** Auto picks a model per message; a manual choice stays fixed unless it can't handle the message (or
  automatic switching is off). Exclusions are hard constraints. Unknown price/context stays "unknown". Model
  layouts are named sets; removed recommended layouts stay hidden.
- **Privacy.** Incognito keeps messages, files, canvas and drafts in memory only (no history, sync, memory or
  project). Accounts are isolated: switching account clears every previous-account surface immediately. The
  privacy shield masks detected personal details before anything is sent. Drafts survive navigation.
- **Repository work.** Plan → approve → editable implementation draft → review blocks → explicit commit/PR. Plan
  approval is bound to plan, repo/branch, chat, snapshot and device. Undo is a revert commit, never a rewrite.
- **Knowledge.** Library → Knowledge imports PDFs/text locally; "Index meaning" explicitly sends text to Gemini
  embeddings with the user's key. Citations keep page/section references.
- **Long chats.** Above 120 messages a window renders; "Show full conversation" or Ctrl/Cmd+F mounts everything.
  The line navigator on the right jumps between questions.
- **Excluded by the owner:** Arabic interface, separate chat folders, the message-list icon/count, chat-tag badges.

## Presentations

Two builds from one source. **Canvas** (`LUMEN_CANVAS=1`) is production. The **ordinary** build is the rollback: keep
it building and working, but design work targets Canvas. Canvas-only code sits behind `src/lib/canvas-presentation.ts`
(swapped for its `.on.ts` module at build time) and Canvas-scoped CSS (`html[data-lumen-canvas]`). On iPhone (iOS 16+
with blur support) Canvas adds **glass** (`html.glass`, `src/lib/glass.ts`, `src/glass.css`): Liquid Glass bars and
composer in the iOS 26 style, the system font, and iOS grouped backgrounds. The material (`--lg-*` in
`canvas-screens.css`) is an even clear tint with a specular rim (bright top-left, softer bottom-right) and a faint glow
inside the edge, never a top sheen or a flat gray; small bar buttons are clear, the larger message box is frosted
(denser tint) so a reply never reads through it. At the top bar and behind the message box, the iOS 26 scroll edge:
what passes under blurs progressively (a masked 8 px blur) and dims only lightly, so it never reads as a band; the
blur pauses while a reply streams. Reading on glass: code blocks are one filled block with plain-text
Run/Copy, tables have no frame (hairline rows), and dragging the conversation down while writing lets the keyboard go.

## Identity

Ink on paper, one voice, light as the only warmth. Lumen should feel like a well-made notebook and a desk lamp, not a
control panel. It is its own app: never copy another product's look (no serif greetings, no terracotta, no warm-brown
dark mode).

- **Mark:** the Crease (a standing page with light through its fold) and the Crease-as-L wordmark, generated by
  `scripts/brand-crease.mjs` into `brand/crease/`, `public-canvas/` and `src/lib/brand-crease-art.ts`; components in
  `src/components/BrandCrease.tsx`. Wordmark 28 px+ (small drawing 16–28, mark alone below 16), one colour only,
  `role="img"` labelled "Lumen". Never recolour the planes, outline, shadow, rotate or close the crease.
- **Colour:** cool neutral ink and paper (`src/app.css` identity section). Accent = ink: Send, switches that are on,
  focus, the model dot; one solid ink pill per screen. Fills are ink at 7% / 12% (hover / current), rims 10%.
  **Lamplight** (`--canvas-lamplight`, Light `#f1e2b6`, Dark `#4d4130`) is the only warm colour: text selection and
  "this one is yours right now" (the active section tab, the Selected chip on the model in use). Never buttons,
  focus or text. Status colours (green, red, orange, blue) only for state. Light and Dark; no True black in Canvas.
- **Type:** Geist (system font on iPhone glass); Geist Mono only for data (code, shortcuts, counts). Four steps per
  page: 28 title, 17 section, 15 rows/body, 13 secondary. List pages share the tokens in `src/app.css` (identity):
  `--type-row` / `--type-detail` / `--type-note` are 17 / 15 / 13 on phones and 15 / 13 / 13 on computers, and
  `--type-large-title` is 34 on phones; all follow the text size (`--fs`). Reading 16.5/1.72 in a 720 px measure. Weights 400/500/600
  and 620–640 for display only. Fields 16 px+ on touch screens. Section labels are sentence case, 13/600 secondary
  (no mono uppercase).
- **Space and shape:** 4 px grid (4, 8, 12, 16, 24). Radii through the `--canvas-radius-*` tokens only: row 10,
  control/menu 14, card 18, panel/sheet 24, pill 999. A box exactly twice its radius tall (the 52 pt iPhone message box,
  26) and tiny tags (≤ 6) are the only literals. Depth from tone and hairlines; shadows (`--layer-shadow`) only on
  floating things.
- **Icons:** Lucide outline, 17–18 px, stroke 1.9; secondary colour at rest, ink when active. No filled or coloured
  icons. Chevron (›) for navigation, never → .

## Calm rules (apply everywhere)

- One container per screen; grouped lists by tone, no card inside a card, no outlines (forced-colours keeps borders).
- Two kinds of button: one solid ink pill for the main action, everything else plain text (with an icon if useful).
- State facts, don't explain: at most one short line under a row; details behind a disclosure.
- Colour only for what needs you; a problem is one line with a coloured rule plus a way to fix it, never raw
  provider error text.
- Show real names: a model id with no catalogue name is shown prettified ("Gemini Flash"), never `gemini-flash-latest`.
- Before adding a control, check it doesn't already exist somewhere else.
- Nothing scrolls sideways at 320 px; touch targets 44 pt on phones; visible 2 px focus; respect Reduce Motion and
  Reduce Transparency (glass turns solid).

## Layout and ownership (one place for each thing)

## Motion

Controls press in 1.5–3.5% and spring back; Reduce Motion keeps them still. Desktop pages crossfade briefly (a view
transition on Canvas).

**Phone navigation (Canvas)** has one owner and one transition, `src/lib/navigation-coordinator.ts` (lazy, touch
devices): every Back swipe and the drawer's swipe go through it, and the old per-screen swipe handlers are gone.
- A swipe from the leading edge on a pushed screen moves that screen with the finger and does what its top-left Back
  does (one level up, see Pages); a right swipe across its content does nothing. On a root screen (the chat, or a
  place chosen in the drawer) the swipe belongs to the drawer (`src/lib/sidebar-gesture.ts`): the drawer and the
  screen move together with the finger, and the screen keeps a 64 pt strip in view (`--cv-drawer`). An open menu or
  list keeps both gestures off. An iOS browser tab leaves Back and Forward to Safari entirely. An iOS Home Screen app
  (iOS 26 gives it Safari's own edge swipe, with stale snapshots) keeps its stack in memory over one browser entry
  (`screen-history.ts`), so the system swipe has nothing to go back to and every swipe is Lumen's; other installed
  apps (Android) keep real history.
- Behind it is what Back restores: the real chat or workspace (still mounted, revealed), or the screen kept when you
  left it (memory only, this account, never incognito or key fields) while the data it shows is unchanged; otherwise a
  plain page. Never a wrong preview. The screen behind moves in from −28% under a 0.08 dim; the moving one has a shadow.
- Release where the finger's speed would carry it past half the width, or a flick, commits (easing back a little at the
  end still commits; a clear reversal or a touch the system cancels stays): exactly one history traversal, and the layers come off once
  the destination has painted. A short, reversed or canceled drag springs back; Browser Back, a resize or an account
  change during a drag stops it with no navigation. Sheets, dialogs, menus and selected text keep the edge too.
- Taps use the same slide: a new step pushes over the screen it leaves, and the app's own Back (the top-left button)
  pops like the gesture. A place chosen in the drawer does not slide: the drawer closes over it, already in place. Reduce Motion keeps the finger tracking but drops the parallax and the slides.
- Tests: `tests/e2e/native-navigation.cjs` (Chromium and WebKit, 390/320, Light/Dark, Reduce Motion, a Safari tab).

Only replies appended to the open chat animate in (220 ms); streaming text fades in over 240 ms. Only replies appended to the open chat animate in (220 ms); streaming text fades in over 240 ms.
Sheets track the finger. Decorative animation pauses offscreen, when hidden or under Reduce Motion. Theme changes
switch instantly. SVG: animate an inner element, never one with a `transform` attribute.

## Where styles live

`src/app.css` (base, ordinary, shared identity; later sections win) → `src/styles/canvas*.css` and component CSS
(Canvas, scoped) → `src/glass.css` (iPhone glass). Put new tokens in the identity section. Don't reuse generic class
names. Canvas CSS has a size budget (`scripts/canvas-budget.mjs`, run in CI).

## Checking a design

Run the app (`.claude/launch.json` → `lumen-canvas`, or `LUMEN_CANVAS=1 npx vite`) with a preview account: set
`localStorage['mr.preview_user']` to `{"uid":"preview-x","email":"x@local.invalid","displayName":"X"}` and reload.
Screenshot helpers live in `tests/e2e/helpers/` (`audit-shots`, `textfit`, `fitscan`); `BROWSER=webkit` uses
Safari's engine. Chromium can't show iPhone glass (it needs an iPhone user agent); use the WebKit helpers or a
device. Physical iPhone, VoiceOver and Dynamic Type are only verified on a device.
