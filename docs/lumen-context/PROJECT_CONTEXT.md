## Product and design philosophy

Lumen is an independent, premium AI workspace for conversation, reading, sustained writing, projects, model selection/routing, providers, usage context and tools. Prioritize **original identity**, clear visual hierarchy, excellent desktop and real-iPhone interaction, accessibility and reliable feature parity.

**Canvas is the owner-selected design foundation, not an implementation freeze.** Use the latest checkpoint for any newer decision or approval. Its established principles include a unified Projects/conversations tree, compact resting composer, progressive controls, reversible expanded writing sheet, comfortable reading typography and refined phone glass. The conversational list is clean, with pinned entries first and others in recent-first order, not date-section headers, unless the owner changes that design choice. These choices are a starting point for quality work, not a prohibition on improving them.

Other products (including 9Router and ChatGPT) may be used as **functional inspiration**, never as a license to duplicate trademarked layouts, proprietary assets or unique screenshots. Routing Center must be a substantial, integrated workspace, not a decorative replica. Retain Lumen's actual model/provider capabilities.

**Native-app-style interaction preference (owner decision, 2026-10-22):** Keep pinch-to-zoom disabled in Lumen's primary chat-style interface; avoid treating a browser-like pinch gesture as a default mobile behavior. Preserve a comfortable readable default scale and support accessible text-size/OS display preferences where feasible. Do not weaken essential accessibility accommodations or extend this decision indiscriminately to document/media views that have their own zoom requirements; handle such cases explicitly in the relevant design review.

**Approved identity (owner decision, 2026-10-23):** The owner chose and approved the final **integrated Crease** identity: the open-laptop/fold-inspired symbol forms the first letter L of the custom `Lumen` wordmark, while the related standalone mark is the app icon. Preserve the two-plane silhouette, intentional opening, optical typography, legibility in monochrome and at small sizes, accessible vector assets and restrained ink/paper design language. Avoid a generic L, duplicate initial, literal laptop pictogram, AI sparkle or decorative gradients. Use the custom wordmark in intentional brand placements and plain text for ordinary mentions. Final artwork approval is distinct from actual merge/deployment status, which must be verified and recorded in `CURRENT_STATUS.md`.

**Quality-first redesign permission (explicit owner decision, 2026-10-23):** Previously implemented, polished, accepted or Gate-approved UI is **not sacred**. Within the currently authorized design and quality scope, proactively redesign, restructure, simplify, remove, or replace any existing component, layout, interaction or flow when doing so will materially improve Lumen. Do not describe meaningful redesign as merely 'refinement' or constrain recommendations to cosmetic changes because the earlier work is already implemented. Prefer the best product outcome over sunk cost. Preserve what genuinely works; challenge weak choices with a concrete improvement and assess tradeoffs using representative desktop/iPhone states, accessibility and regression evidence proportionate to the risk. Avoid change solely for novelty and avoid reopening decisions without a quality rationale. Current owner preferences and approved product direction remain the baseline, but they do not protect an inferior implementation from redesign. This permission is **not** blanket authority to initiate unrelated product phases or to alter protected auth/security/network boundaries, incur costs, approve Gates, merge or deploy; those remain governed by current explicit authorization.

## Progress reporting across distinct workstreams

The current seven-phase Lumen design/UX quality program is **not** the old Blackout or Dynamic Model Picker weighted scope. Never present a historical scope-specific score as **overall Lumen completion**, and never carry it forward with a zero change simply because a new design slice did not fit old weights. Report shipped/accepted phases, in-review slices, tested versus deployed evidence, remaining work and current blockers. An overall percent may be reported **only** if a scope-matching, owner-approved weighted baseline exists and is actually recalculated with supported evidence; otherwise explicitly say no defensible overall percentage is currently defined. Preserve older weighted calculations in historical records for their respective scopes; do not rewrite them or invent replacement scores.

## Stable engineering guarantees

- Preserve canonical state, model/provider routing, policies, permissions and usage sources. Existing visual components may be substantially rewritten or replaced if their contracts and feature parity are protected; do not create conflicting parallel state or routing. Preserve composer draft/selection/IME/undo, Send/Stop, attachments, nested menus, accessibility, account isolation and data integrity.
- Never claim a provider limit, usage estimate, price, entitlement, test pass, release, security property or deployment is verified without appropriate evidence. Distinguish implementation, test, owner review, acceptance and production status.
- Validate on actual mobile Safari for material keyboard, safe-area, touch, blur, dictation/IME and VoiceOver behavior as required by the relevant acceptance plan. Desktop and simulated WebKit/Chromium tests support, but do not replace, required physical-device results.
- Keep review/proof code and **synthetic test identities/data** isolated from real inference, production Firebase/accounts, secrets and service workers. Preserve privacy/auth boundaries.
- The iPhone QA workflow should be **private, reusable, access-controlled, temporary/revocable and convenient**. Favor the owner's currently authorized solution from the live checkpoint; avoid unnecessary new links, new infrastructure or repetitive setup.
- **Strict $0 incremental spending** for private iPhone QA and its operation. Do not enable billed consumption, payment methods, upgrades, paid seats, checkout, additional paid dependencies or public preview hosting without distinct explicit owner authorization. When free limits, charges or safe access are uncertain, use the existing approved route or pause the risky action; never weaken isolation to save money.

## Authority, approval and agents

- **Owner** exclusively grants design/Gate approvals, new phase authorization when required, production integration, merges, deployments, spending, and consequential network/auth/access changes.
- **Coding agent:** Claude Code, Codex or another owner-selected capable tool. The *active agent* and currently authorized scope are dynamically maintained in [CURRENT_STATUS.md](CURRENT_STATUS.md), never assigned here permanently. Preserve completed work and related WIP during handoffs.
- **ChatGPT:** product/engineering partner, planner, practical design reviewer, agent brief author, connected-tool operator and cross-agent context coordinator.
- A previous Gate approval is a dated historical fact, not permission for other Gates or production release. Never infer authorization from successful tests, positive feedback, an unreviewed proposal or a past phase. Check the current state before consequential operations.

## Working style — capable, proactive and low friction

Work toward meaningful outcomes, not process for its own sake. Prefer a **solution-first recommendation and executable action** over lengthy audits and repeated questions. Use available GitHub, project/file, search, coding, browser/Work and artifact tools when authorized and actually connected; never invent tools or background progress.

Accept coherent coding-agent reports as the routine working basis, clearly labelling provenance. Investigate deeper only when evidence conflicts, a failure is material, the owner requests it or security, privacy, cost, account boundaries, Gate acceptance or production/release is at stake. Coding agents still run proportionate tests. Within an authorized quality milestone, carry out justified substantial UI replacements as well as small fixes without pointless repeated approval pauses; batch proportionate tests sensibly. Significant scope beyond that milestone still follows the owner-authorization rules above.

## Cross-agent continuity and confidentiality

Every agent opening a Lumen work session consults the [live checkpoint](CURRENT_STATUS.md) and [README.md](README.md), compares the latest meaningful owner direction/handoff, **updates missing status itself if it has write access**, and does nothing if another agent has already updated it. Repeat at meaningful milestones. Maintain durable policies here **only when those policies change**. Never require the owner to reupload Markdown for ordinary status changes. This is agent-triggered, not always-on background synchronization.
