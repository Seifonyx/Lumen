## 1. STRICT PHASED EXECUTION — NEVER ATTEMPT THE ENTIRE REVAMP AT ONCE

This project is a major design, product, security, and feature overhaul.

**You must execute it progressively in small, independently recoverable, verifiable milestones rather than attempting to implement the entire project in one session.**

This requirement is especially important because AI coding agents have limited context windows, usage allowances, and execution time.

A complete overhaul attempted in one pass risks rushed design decisions, excessive complexity, incomplete integration, regressions, poor verification, and lost progress.

Instead:

1. Divide the entire approved scope into clearly defined phases.
2. Break large phases into manageable implementation milestones.
3. Establish explicit acceptance criteria for every milestone.
4. Complete one coherent milestone before beginning another.
5. Run appropriate verification after every meaningful implementation change.
6. Review the actual result before awarding completion credit.
7. Update the repository's implementation plan and cross-agent handoff.
8. Commit and push coherent, verified progress safely.
9. Record the exact next task.
10. Continue with the next approved milestone when no user approval or safety gate is outstanding.

**Do not attempt to finish every phase in a single session.**

Work through as many safely verifiable milestones as the execution window allows, without sacrificing quality or recoverability.

Do not impose arbitrary delays between phases. Phased execution exists to improve correctness and continuity, not slow development unnecessarily.

## 2. IDENTITY-FIRST MILESTONE — MANDATORY USER APPROVAL

**Lumen's new visual identity must be established and approved before extensive implementation of the redesigned application.**

This is the most important addition to the original prompt.

The user has previously rejected multiple redesign attempts because they appeared generic, rushed, insufficiently transformative, or visually inferior to the existing application.

Do not repeat this failure.

Before large-scale UI implementation:

1. Research excellent modern application design.
2. Analyze 9Router's reference screenshots and design patterns.
3. Study Lumen's existing identity and functionality.
4. Explore several genuinely distinct black-and-white design directions.
5. Evaluate their originality, visual quality, usability, and brand recognition.
6. Select and refine the strongest candidates.
7. Produce meaningful visual concepts using Lumen's actual interface and components where practical.
8. Show full-size desktop and mobile examples.
9. Explain how the new identity differs from both the original Lumen and 9Router.
10. **Obtain the user's explicit visual approval before proceeding with the extensive redesign.**

Do not treat a theme change, color replacement, or generic mockup as a complete identity proposal.

The new identity must address typography, geometry, composition, iconography, interaction, navigation, surfaces, and overall product character.

The user is intentionally abandoning the old lime-forward visual archetype in favor of a sophisticated monochrome identity.

This decision permits reconsidering existing brand elements, including the logo, where appropriate. Preserve recognizable Lumen characteristics when they strengthen the brand, but do not retain legacy aesthetics merely out of inertia.

The new identity must be **distinctive, memorable, premium, and unmistakably Lumen**.

Use actual working-component proofs when needed to establish visual feasibility, but keep experimental changes isolated and unmerged during aesthetic review.

**The first mandatory user approval gate is the identity itself, not an extensively implemented application.**

## 3. REVISED MASTER IMPLEMENTATION PHASES

Execute the revamp using the following high-level structure.

### PHASE 1 — Research, Audit, and Requirements Recovery

Recover the complete project context using PROJECT CONTINUUM v2.0.

Analyze:

- Lumen's existing application, features, and architecture.
- Current design weaknesses.
- Previous failed redesign attempts.
- The provided 9Router reference pack.
- Relevant public 9Router feature documentation.
- Other outstanding applications with strong visual identities.
- Security, privacy, and architectural constraints.

The supplied reference pack may contain screenshot download manifests rather than embedded image files. Verify its contents and retrieve accessible references where permitted. Never claim to have visually inspected images that were not actually accessed.

Establish the feature comparison and complete revamp requirements.

**Checkpoint:** Verified baseline, reference analysis, and approved-scope understanding.

### PHASE 2 — New Lumen Identity Development

Develop the new black-and-white visual direction.

Explore distinct approaches to:

- Branding and logo.
- Typography.
- Workspace geometry.
- Navigation.
- Iconography.
- Depth and material systems.
- Light, dark, and true-black appearances.
- Interactions and motion.
- Visual character and recognizability.

Use semantic warning, error, and status colors where accessibility and clarity require them; monochrome branding must not obscure important system states.

Compare multiple credible concepts rather than producing nearly identical color variations.

Show the strongest direction with actual-app visual evidence where feasible.

**Checkpoint: Explicit user approval of Lumen's new visual identity.**

Do not continue into extensive interface implementation without this approval.

### PHASE 3 — Shared Design System Foundation

Implement the approved identity as a maintainable design system.

Establish:

- Semantic design tokens.
- Typography rules.
- Spacing and density systems.
- Component geometry.
- Monochrome color hierarchy.
- Interaction states.
- Icons and consistent controls.
- Materials, elevation, and motion.
- Responsive behavior.

Preserve existing application functionality.

**Checkpoint:** Verified design-system foundation, ready for integration into major surfaces.

### PHASE 4 — Core Interface Transformation

Redesign the most important application surfaces in smaller milestones.

Prioritize:

- Desktop application shell.
- Sidebar and navigation.
- Main workspace.
- Chat and composer.
- Dashboard or home experience.
- Primary model and provider controls.
- Core mobile navigation and interaction.

Each surface must follow the approved identity.

Produce matched before-and-after screenshots.

**Checkpoint:** A substantially transformed, functioning core Lumen experience, reviewed visually before production integration.

### PHASE 5 — 9Router-Inspired Feature Expansion

Use the previously documented feature comparison to identify meaningful capability improvements.

Evaluate areas such as:

- Provider management.
- Model catalog and selection.
- Routing and automatic fallback.
- Usage and quota tracking.
- Configuration workflows.
- Operational status and diagnostics.
- Account management.
- Routing visibility and controls.
- Other relevant 9Router capabilities.

For every proposed addition, determine its value, technical feasibility, security implications, and fit within Lumen.

Do not treat all 9Router features as automatically suitable or authorized.

Preserve existing Lumen capabilities and avoid duplicating completed work.

If capabilities require secure backend or local-service infrastructure not currently present, design and verify those dependencies rather than assuming a browser-only application can safely reproduce them.

Implement approved features individually or in small, coherent groups.

**Checkpoint after each feature:** Functionality implemented, integrated, tested, documented, and safely synchronized.

### PHASE 6 — Secondary Interfaces and Complete Visual Consistency

Extend the approved identity across remaining application surfaces:

- Settings.
- API keys.
- Model Picker and Layouts.
- Projects.
- Tools.
- Library.
- Canvas.
- Study.
- Compare.
- GitHub workflows.
- Supporting dialogs, menus, sheets, and complex states.

Ensure that the application looks like one complete, purposefully designed product.

**Checkpoint:** Complete visual coverage and preserved feature parity.

### PHASE 7 — Security, Performance, and Reliability Hardening

Conduct targeted review of:

- Credential storage and handling.
- Account isolation.
- Provider permissions.
- Authentication and authorization.
- Sensitive-data boundaries.
- Routing and fallback correctness.
- Privacy controls.
- Dependency security.
- Application responsiveness.
- Accessibility.
- Cross-browser and cross-device behavior.

Security review must also occur during earlier feature work; this phase is the comprehensive final hardening pass, not the first time security is considered.

**Checkpoint:** Relevant issues resolved and verification evidence documented.

### PHASE 8 — Final Visual Refinement and Production Readiness

Inspect the complete application at representative desktop, tablet, and mobile sizes.

Verify light, dark, and true-black appearances.

Evaluate complex content, loading, errors, long labels, keyboard interactions, and responsive layouts.

Check for inconsistencies, awkward spacing, poor hierarchy, generic elements, and weak visual composition.

Compare actual screens against the approved design direction and the original application.

Obtain final visual acceptance where required.

Complete necessary testing, documentation, release verification, and deployment.

**Checkpoint:** Approved, tested, production-verified revamp with synchronized handoff documentation.

## 6. PERMANENT IDENTITY PROTECTION DIRECTIVE

Identity is the highest-risk failure point in this revamp.

If an implemented design feels:

- too similar to 9Router,
- visually generic,
- anonymous,
- unnecessarily minimal,
- inconsistent with Lumen's approved identity,
- less sophisticated than the original application,
- or like an unrefined component-library template,

**reject or revise that direction before treating it as successful.**

Lumen must emerge as its own product, not a black-and-white restyling of someone else's application.

The black-and-white identity must have recognizable character through composition, typography, geometry, interaction, and purposeful details.

Do not sacrifice identity for feature parity.

Do not sacrifice functionality for visual minimalism.

Do not sacrifice security or maintainability for faster implementation.

The target is a distinctive, visually exceptional, highly capable application that clearly belongs to Lumen.
