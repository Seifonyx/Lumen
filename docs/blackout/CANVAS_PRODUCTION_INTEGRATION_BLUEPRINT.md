## Data, security and compatibility requirements

1. **Auth is above presentation.** App's `authed === null`, login and `accessDenied` branches remain authoritative. Do not render an approved-design shell containing cached private content before access checks. On logout/account switch, close menus/sheets/provider selection and discard stale references before another account can interact. Hidden DOM must not retain another account's information.
2. **Keep storage stable.** Retain account-specific IndexedDB and chat sync, account/session/revision guards, the Composer draft key `mr.draft.<uid>.<chat-or-new>` and existing legacy-owner migration. Do not migrate chat/project/provider/Layout schemas to change appearance. Any later schema change requires old-version fixtures, additive versioning, dry-run/atomic failure handling and a rollback-readable representation before authorization.
3. **UI preferences are not credentials.** If tree disclosure is promoted, use a bounded, validated versioned per-account local preference; no undefined UID, titles, prompts or credentials in the payload. Load/reset synchronously at account boundaries so old disclosure state is not briefly visible or written to another account. Storage denial/corrupt JSON must safely fall back. Do not read proof key `lumen.blackout.canvasNav.<uid>` as production truth. Keep current device-wide `mr.sidebarCollapsed` compatibility unless a separately reviewed migration is chosen.
4. **Incognito remains ephemeral.** No history/search/tree/storage persistence, saved memories or implicit project assignment for temporary chats. Expanding/collapsing, closing a drawer or toggling appearance must not persist their draft. Explicit downloads and repository writes retain existing consent semantics.
5. **One credential and settings save path.** Reuse masked Settings/ProviderConnections drafts, saved-state distinction, pending durable writes and current session checks. Provider filters may read only scoped key-presence booleans, not copy secrets into a view model or DOM. Changing credentials cancels stale discovery/check/inference work. No new storage copies or encryption claims.
6. **Network and billing remain canonical.** No traffic when opening a provider page solely to create a health label. Explicit connection checks retain their real costs/disclosures. Never broaden provider/relay endpoint allowlists, remove privacy review, enable paid providers from saved keys or forward private context to a new gateway/compressor. Unknown data does not become a fabricated healthy/free/zero-cost state.
7. **Safe rendering and external writes.** Keep Markdown sanitization, attachment extraction limits, repository account/branch/snapshot-bound plan approvals and explicit commit/PR flow. Preview fixtures, logs and captures use synthetic identifiers and transport interception; public checkpoints include metadata and links only, no personal data, credentials, private transcripts or raw provider failures.
8. **Permission expansion remains a separate decision.** This blueprint proposes no new backend, dependency, service worker behavior, OAuth flow, analytics service, credential vault or cloud rules. A display flag is not authorization or account isolation. Do not weaken security controls to obtain device evidence.
